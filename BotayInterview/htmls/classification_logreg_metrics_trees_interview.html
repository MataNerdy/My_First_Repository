Классификация — задача, где модель должна выбрать класс объекта из конечного набора классов.

  • письмо → spam / not spam;
  • картинка → cat / dog / bird;
  • клиент → уйдёт / не уйдёт.

Регрессия предсказывает числовое значение: стоимость, температуру, время доставки и т. п.

Классификация → дискретная категория. Регрессия → числовое значение.
На собесе: «В классификации целевая переменная категориальная, в регрессии — числовая. Модель классификации часто выдаёт score или вероятность, а уже затем по порогу выбирается класс.»

Линейная регрессия строит:

z = wᵀx + b,    ŷ = z

Логистическая регрессия сначала тоже считает линейную комбинацию:

z = wᵀx + b

а затем пропускает её через sigmoid:

p = σ(z) = 1 / (1 + e−z)

Получаем p ∈ (0, 1), что интерпретируем как P(y=1|x).

Далее можно применить порог, например:

p ≥ 0.5 → ŷ = 1
Линейная регрессия предсказывает число напрямую. Логистическая — вероятность класса через sigmoid.

Да. Хотя sigmoid нелинейна, логистическая регрессия остаётся линейной моделью по признакам.

При пороге 0.5:

σ(wᵀx + b) ≥ 0.5 ⇔ wᵀx + b ≥ 0

Граница решения:

wᵀx + b = 0

В 2D это прямая, в 3D — плоскость, в nD — гиперплоскость.

Ещё один способ увидеть линейность:

log(p / (1 − p)) = wᵀx + b
LogReg — линейная модель, потому что log-odds линейно зависят от признаков и граница решения линейна.

Loss function используется для обучения: оптимизатор пытается её минимизировать.

Loss → gradient → update weights

Метрика используется для оценки качества модели человеком или для выбора модели.

Примеры метрик: Accuracy, Precision, Recall, F1, ROC-AUC.

Loss должна быть удобна для оптимизации. Метрика должна быть полезна для оценки качества.

Например, можно обучать по Cross-Entropy, а качество смотреть по F1.

Да. Это скорее роль величины, чем два непересекающихся типа функций.

Например, MSE можно:

  • минимизировать как loss;
  • показывать как метрику на validation.

То же возможно с MAE или LogLoss.

Но не каждая хорошая метрика является хорошим loss. Accuracy и F1 неудобны для обычного градиентного обучения, поскольку содержат недифференцируемые операции и меняются скачками.

В бинарной классификации есть два класса:

y ∈ {0, 1}

Модель может выдавать logit:

z ∈ (−∞, +∞)

или после sigmoid:

p = P(y=1|x) ∈ (0,1)

Тогда:

P(y=0|x) = 1 − p
Для бинарной классификации достаточно одного выхода.

Для одного объекта:

L = −[ y log p + (1 − y) log(1 − p) ]

Если y=1:

L = −log p

Если y=0:

L = −log(1 − p)

Для датасета:

L = −(1/N) Σ [ yᵢ log pᵢ + (1−yᵢ) log(1−pᵢ) ]

Они появляются естественно из Maximum Likelihood Estimation.

Вероятность всего датасета — произведение вероятностей отдельных объектов:

P(D|θ) = ∏ P(yᵢ|xᵢ, θ)

Логарифм превращает произведение в сумму:

log P(D|θ) = Σ log P(yᵢ|xᵢ, θ)

Сумму удобнее оптимизировать численно. Чтобы максимизацию превратить в минимизацию, ставим минус:

Loss = −log Likelihood

Кроме того, логарифм сильно штрафует уверенные ошибки:

−log(0.9) ≈ 0.105     −log(0.01) ≈ 4.605
Логарифм одновременно даёт удобную сумму вместо произведения и сильно наказывает уверенные неправильные прогнозы.

MLE — Maximum Likelihood Estimation.

Идея: выбрать такие параметры модели, при которых наблюдавшиеся данные были бы максимально вероятными.

θ* = arg maxθ P(D|θ)

Если модель дала настоящим классам вероятности 0.9, 0.8 и 0.7, то likelihood:

0.9 × 0.8 × 0.7

MLE ищет параметры, максимизирующие такое произведение на всём датасете.

Для бинарной классификации:

P(yᵢ|xᵢ) = pᵢyᵢ(1−pᵢ)1−yᵢ

Likelihood:

L = ∏ pᵢyᵢ(1−pᵢ)1−yᵢ

Логарифмируем:

log L = Σ [ yᵢ log pᵢ + (1−yᵢ) log(1−pᵢ) ]

MLE максимизирует log-likelihood. Это эквивалентно минимизации отрицательного log-likelihood:

−log L = −Σ [ yᵢ log pᵢ + (1−yᵢ) log(1−pᵢ) ]
Для логистической регрессии с Bernoulli likelihood: MLE ⇔ минимизация Binary Cross-Entropy.
Реально +Реально −
Предсказали +TPFP
Предсказали −FNTN
  • TP — предсказали 1, реально 1.
  • FP — предсказали 1, реально 0.
  • TN — предсказали 0, реально 0.
  • FN — предсказали 0, реально 1.
Precision = TP / (TP + FP)

Из всех, кого назвали положительными, сколько действительно положительные?

Recall = TP / (TP + FN)

Из всех реально положительных сколько мы нашли?

Accuracy = (TP + TN) / (TP + TN + FP + FN)

Какую долю всех объектов классифицировали правильно?

F₁ = 2 · Precision · Recall / (Precision + Recall)

Через confusion matrix:

F₁ = 2TP / (2TP + FP + FN)
F1 — гармоническое среднее Precision и Recall.

Пусть:

Precision = 1,    Recall = 0.1

Арифметическое среднее:

(1 + 0.1) / 2 = 0.55

Получается 55%, хотя модель находит только 10% положительных объектов.

F1:

F₁ = 2 · 1 · 0.1 / 1.1 ≈ 0.182
Гармоническое среднее сильнее тянется к меньшему из двух значений, поэтому высокий F1 требует одновременно хороших Precision и Recall.

Можно было бы использовать:

G = √(Precision · Recall)

Но геометрическое среднее слабее штрафует дисбаланс.

Для P=1, R=0.1:

G ≈ 0.316,    F₁ ≈ 0.182

Для положительных чисел:

H ≤ G ≤ A

где H — гармоническое, G — геометрическое, A — арифметическое.

F1 — не «закон природы», а удобная договорённость, хорошо штрафующая перекос между Precision и Recall.

Для обычной бинарной классификации, если все три величины считаются по одной confusion matrix, — нет.

Пусть число реально положительных объектов равно P.

Recall = TP/P = 0.92 → TP = 0.92P

Из Precision:

0.19 = TP/(TP+FP)

откуда:

FP ≈ 3.92P

Минимальный Accuracy будет при TN=0:

Accuracymin = 0.92P / (P + 3.92P) ≈ 0.187
Значит при таких Precision и Recall Accuracy не может быть ниже примерно 18.7%. Значение 10% невозможно.

Оговорка: в multiclass с разными способами averaging ситуация может быть другой.

Общая формула:

Fβ = (1+β²)PR / (β²P + R)

Через confusion matrix:

Fβ = (1+β²)TP / ((1+β²)TP + β²FN + FP)
  • β = 1 → F1;
  • β > 1 → сильнее ценим Recall;
  • β < 1 → сильнее ценим Precision.

Для F2:

F₂ = 5PR / (4P + R)

Для очень большого β:

Fβ → Recall
F100500 почти полностью будет определяться Recall.

ROC — Receiver Operating Characteristic.

По оси X:

FPR = FP / (FP + TN)

По оси Y:

TPR = TP / (TP + FN) = Recall

При изменении threshold получаем разные точки ROC-кривой.

X = FPR,    Y = TPR

Идеальный классификатор идёт к точке (0,1). Случайный — примерно вдоль y=x.

ROC-AUC — площадь под ROC-кривой. Её также можно интерпретировать как вероятность того, что случайный positive получит score выше случайного negative.

Не берутся равномерные пороги 0, 0.05, 0.10, 0.15...

Пусть модель дала scores:

0.92, 0.81, 0.63, 0.63, 0.41, 0.12

Достаточно рассматривать пороги в местах, где реально меняется набор predicted positive, то есть по уникальным score:

0.92 > 0.81 > 0.63 > 0.41 > 0.12
  1. Сортируем объекты по score от большего к меньшему.
  2. Начинаем с ситуации «все отрицательные».
  3. Постепенно снижаем threshold.
  4. При пересечении score объект становится predicted positive.
  5. Обновляем TP/FP и пересчитываем TPR/FPR.
ROC в первую очередь зависит от ранжирования объектов по score, а не от конкретной шкалы вероятностей.

Начинаем со всех объектов в корневом узле.

Алгоритм ищет вопрос вида:

xⱼ < t ?

Например: age < 35?

Получаем левую и правую группы и оцениваем, стало ли разделение «чище».

Лучший split выбирается, после чего процесс рекурсивно повторяется для дочерних узлов.

Остановка происходит, когда:

  • достигнут max_depth;
  • объектов слишком мало;
  • улучшение слишком мало;
  • узел уже чистый;
  • сработали другие ограничения.
Дерево строится жадно: на каждом шаге выбирается лучшее локальное разбиение.

Для каждого кандидата на split считаем уменьшение нечистоты.

Например Gini:

Gini = 1 − Σ pₖ²

Для чистого узла Gini = 0. Для бинарного узла 50/50 Gini = 0.5.

После split:

Iafter = (NL/N) IL + (NR/N) IR

Уменьшение impurity:

ΔI = Iparent − Iafter
Выбираем split с максимальным уменьшением impurity.

Вместо Gini можно использовать энтропию:

H = −Σ pₖ log pₖ

Для числового признака нет смысла проверять каждый real number — достаточно порогов между соседними уникальными значениями, где меняется разделение объектов.

Основные способы:

  • max_depth — ограничить глубину;
  • min_samples_split — минимум объектов для split;
  • min_samples_leaf — минимум объектов в листе;
  • max_leaf_nodes — ограничить число листьев;
  • max_features — ограничить число признаков при поиске split;
  • min_impurity_decrease — требовать достаточного улучшения;
  • pruning — обрезать лишние ветви.

В sklearn для cost-complexity pruning есть:

ccp_alpha

Получим underfitting.

Дерево слишком простое и не может описать закономерности.

train score ↓     validation score ↓
Слишком короткое дерево → высокий bias.

Например max_depth=1 даёт decision stump — всего одно разделение.

Дерево начинает запоминать конкретные объекты и шум.

Можно дойти почти до ситуации:

один лист ≈ один объект

Тогда:

train accuracy ≈ 100%,    validation/test хуже
Слишком глубокое дерево → overfitting и высокая variance.
  • легко переобучаются;
  • нестабильны: небольшое изменение данных может сильно поменять дерево;
  • предсказания кусочно-постоянные;
  • плохо экстраполируют;
  • границы решения у обычного дерева ступенчатые и параллельны осям;
  • одиночное дерево часто хуже ансамблей;
  • при действительно линейной зависимости линейная модель может быть проще и эффективнее.
Дерево гибче, но за эту гибкость платит большей variance.
  • моделируют нелинейности;
  • автоматически находят взаимодействия признаков;
  • не требуют scaling;
  • мало предположений о форме зависимости;
  • достаточно интерпретируемы;
  • хорошо ловят сложные decision boundaries;
  • являются основой Random Forest, Gradient Boosting, XGBoost, LightGBM, CatBoost.
Для дерева правило вида «если x₁ > a и x₂ < b» возникает естественно. Линейной модели такие взаимодействия часто приходится добавлять явно.

StandardScaler:

x′ = (x − μ) / σ

Особенно scaling важен при регуляризации:

L₂ = λ Σ wⱼ²
L₁ = λ Σ |wⱼ|

Без scaling величина коэффициента зависит от единиц измерения признака, поэтому регуляризация воздействует на признаки неравномерно.

Теоретически LogReg может работать без scaling. Практически scaling обычно улучшает оптимизацию и особенно важен при L1/L2.
