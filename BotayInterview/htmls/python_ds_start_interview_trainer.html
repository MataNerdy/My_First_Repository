Окружения
Что такое virtual environment и зачем он нужен?

Virtual environment (виртуальное окружение) — изолированное окружение Python для конкретного проекта. У него свой набор установленных пакетов (site-packages) и свой путь к интерпретатору.

  • разные проекты могут использовать разные версии одних и тех же библиотек;
  • зависимости проекта не засоряют глобальную установку Python;
  • окружение легче воспроизвести через requirements.txt, pyproject.toml, lock-файл и т. п.
python -m venv .venv
source .venv/bin/activate   # macOS / Linux
# .venv\Scripts\activate  # Windows
Собеседовательная формулировка: venv решает прежде всего проблему изоляции зависимостей разных проектов.

✅ Что должен услышать проверяющий

  • изоляция зависимостей
  • разные версии пакетов для разных проектов
  • свой site-packages
  • воспроизводимость окружения

🎯 Допвопрос

Чем venv отличается от Docker?

Ответ на допвопрос

venv изолирует в основном Python-интерпретатор и Python-пакеты; Docker изолирует приложение шире: файловую систему, системные библиотеки, процессы, сетевые настройки и т. д.

Какие проблемы могут возникнуть при использовании глобальной установки пакетов?
  • Конфликты версий: проекту A нужен lib==1.x, проекту B — lib==2.x.
  • Невоспроизводимость: трудно понять, какие зависимости реально нужны конкретному проекту.
  • Загрязнение окружения: глобально накапливаются десятки не связанных пакетов.
  • Права доступа: глобальная установка иногда требует повышенных прав.
  • Риск сломать инструменты: обновление общего пакета может повлиять на другие проекты или системные утилиты.
Поэтому нормальный дефолт для проекта — отдельное окружение.

  • конфликт версий
  • невоспроизводимость
  • загрязнение глобального Python
  • проблемы с правами/другими проектами

Чем отличается класс от объекта? Приведите пример.

Класс — описание/шаблон типа: какие данные и поведение будут у его экземпляров. Объект (экземпляр) — конкретная сущность, созданная по этому классу.

ООП
Что такое инкапсуляция, полиморфизм, наследование?

Инкапсуляция — объединение состояния и поведения внутри объекта и работа с ним через понятный интерфейс. В Python нет жёсткого private как в некоторых языках: используются соглашение _name, name mangling для __name, свойства и методы.

Наследование — создание нового класса на основе существующего: подкласс получает его поведение и может расширять/переопределять его.

Полиморфизм — один интерфейс, разные реализации. В Python это часто проявляется через duck typing:

def make_sound(animal):
    animal.sound()  # не важно, Cat это или Dog — важен интерфейс

✅ Что должен услышать проверяющий

  • инкапсуляция — интерфейс к состоянию/поведению
  • наследование — базовый и дочерний класс
  • полиморфизм — один интерфейс, разные реализации
  • duck typing

🎯 Допвопрос

Что предпочтительнее: наследование или композиция?

Ответ на допвопрос

Зависит от модели. Наследование хорошо выражает отношение «is-a», композиция — «has-a» и обычно даёт меньше связности.

ООП
Что такое self в методах класса и почему его нужно указывать явно?

self — ссылка на конкретный экземпляр, для которого вызван instance-метод.

class User:
    def hello(self, name):
        return f"{self}: hello, {name}"

u = User()
u.hello("Ann")

Концептуально вызов u.hello("Ann") близок к User.hello(u, "Ann"): объект u автоматически связывается с первым параметром метода.

self — соглашение об имени, не ключевое слово. Но параметр для экземпляра нужен, если это обычный instance method.

✅ Что должен услышать проверяющий

  • ссылка на экземпляр
  • через self доступны атрибуты объекта
  • obj.m(x) ≈ Class.m(obj, x)
  • self — соглашение имени

🎯 Допвопрос

Почему у @staticmethod нет self?

Ответ на допвопрос

Статический метод не связывается ни с экземпляром, ни с классом; Python не подставляет ему первый аргумент автоматически.

ООП
Можно ли создать класс без __init__? Если да, то как будет работать его инициализация?

Да. Если класс не определяет __init__, он наследует его от базового класса. Для простого класса это в итоге object.__init__.

class Empty:
    pass

x = Empty()  # корректно

Сам объект всё равно создаётся — за создание отвечает __new__. __init__ лишь инициализирует уже созданный экземпляр.

Если унаследованный __init__ не принимает переданные аргументы, вызов вроде Empty(1) завершится TypeError.

✅ Что должен услышать проверяющий

  • да
  • __init__ наследуется
  • создание делает __new__
  • object.__init__ для простого случая

🎯 Допвопрос

Ответ на допвопрос

Технически да: это повторно вызовет метод инициализации на уже существующем объекте, но новый объект не создаст.

HashMap
Как реализованы словари в Python? Какова временная сложность операций?

В CPython dict реализован как хэш-таблица. Для ключа вычисляется hash(key), по нему выбирается позиция; при коллизиях таблица ищет другую позицию по последовательности проб.

Современный CPython использует компактную организацию словаря: индексы таблицы отделены от плотного массива записей. Порядок вставки словаря сохраняется.

ОперацияСредняяХудшая
d[key], key in dO(1)O(n)
вставка / обновлениеO(1) амортизированноO(n)
удалениеO(1) амортизированноO(n)
обход всех элементовO(n)O(n)
Почему «в среднем»? Из-за коллизий и периодических resize таблицы.

✅ Что должен услышать проверяющий

  • хэш-таблица
  • hash(key)
  • коллизии и probing
  • O(1) в среднем
  • O(n) в худшем случае

🎯 Допвопрос

Что происходит при коллизии хэшей двух разных ключей?

Ответ на допвопрос

Одинаковый хэш не означает равенство. Таблица пробует другие позиции и для кандидатов проверяет равенство ключей через ==/__eq__.

HashMap
Почему ключом в словаре может быть только хэшируемый тип?

Словарь должен быстро находить позицию ключа по его хэшу. Поэтому ключ должен быть hashable:

  • иметь хэш, который не меняется, пока объект используется ключом;
  • быть сравнимым на равенство;
  • соблюдать правило: если a == b, то hash(a) == hash(b).

Если бы хэш ключа изменился после вставки, словарь искал бы его уже «не там», где он был сохранён.

Обычно hashable: int, str, bytes, frozenset, кортеж из хэшируемых элементов. Обычно unhashable: list, dict, set.

✅ Что должен услышать проверяющий

  • стабильный hash
  • равные объекты → одинаковый hash
  • словарь ищет по hash
  • mutable контейнеры обычно unhashable

🎯 Допвопрос

Обязательно ли хэшируемый объект должен быть неизменяемым?

Ответ на допвопрос

Строго логически — нет: пользовательский объект может быть mutable и hashable. Но те части состояния, от которых зависят __hash__ и __eq__, нельзя менять, пока объект является ключом.

HashMap
Что произойдёт, если изменить список внутри кортежа, который был ключом в словаре?

Это вопрос-ловушка: такой кортеж изначально нельзя использовать как ключ, если внутри него есть обычный list.

key = (1, [2, 3])
d = {key: "value"}
# TypeError: unhashable type: 'list'

Хэш кортежа зависит от хэшей его элементов. Если хотя бы один элемент нехэшируемый, весь кортеж нехэшируем.

Поэтому стадии «изменить список после того, как кортеж стал ключом» здесь не наступает.

✅ Что должен услышать проверяющий

  • сценарий невозможен
  • list unhashable
  • tuple hashable только если все элементы hashable
  • TypeError

List / complexity
Какая временная сложность append в список?

list.append(x) — O(1) амортизированно.

Обычно у списка есть запас свободной ёмкости, поэтому новый элемент просто записывается в следующую ячейку. Но иногда ёмкость заканчивается: CPython выделяет более крупный массив и переносит ссылки на элементы — такой отдельный append может стоить O(n).

Поэтому на длинной серии добавлений средняя стоимость одного append остаётся O(1).

✅ Что должен услышать проверяющий

  • O(1) амортизированно
  • иногда O(n) при resize
  • list хранит динамический массив
  • есть запас capacity

🎯 Допвопрос

Чем append(x) отличается по сложности от lst = lst + [x]?

Ответ на допвопрос

append меняет существующий список и амортизированно O(1); конкатенация создаёт новый список и копирует элементы, поэтому O(n).

Оценка друга:
13
List / complexity
Что такое амортизированная временная сложность и почему у списка append не всегда O(1)?

Амортизированная сложность оценивает среднюю стоимость операции на последовательности операций, даже если отдельные операции иногда дорогие.

Для списка большинство append — O(1). Когда внутренний массив переполняется, нужен resize и копирование примерно O(n). Но resize случается не каждый раз, потому что память выделяется с запасом.

В результате серия из n добавлений занимает O(n) суммарно, значит один append — O(1) амортизированно.

✅ Что должен услышать проверяющий

  • усреднение по серии операций
  • обычные append O(1)
  • resize O(n)
  • редкие дорогие операции распределяются по дешёвым

🎯 Допвопрос

Амортизированная O(1) — это то же самое, что average-case O(1)?

Ответ на допвопрос

Нет. Амортизированный анализ даёт гарантию на стоимость последовательности операций без вероятностного предположения о входах; average-case обычно опирается на распределение входов/случаев.

List / complexity
А вставка в начало списка сколько занимает по времени и памяти?

lst.insert(0, x) требует сдвинуть все существующие ссылки на один индекс вправо, поэтому время O(n).

По памяти:

  • если текущей ёмкости хватает — дополнительная рабочая память порядка O(1);
  • если нужен рост backing array — может временно потребоваться O(n) дополнительной памяти для нового массива;
  • сам список из n элементов в любом случае занимает O(n) памяти.
Если часто добавляем в начало, обычно лучше collections.deque.appendleft(), а не list.

✅ Что должен услышать проверяющий

  • время O(n)
  • все элементы сдвигаются
  • при resize возможна O(n) память
  • для головы лучше deque

🎯 Допвопрос

Почему deque.appendleft() лучше для частых вставок в начало?

Ответ на допвопрос

Deque спроектирован для O(1) добавления/удаления с обоих концов и не требует сдвигать все элементы как непрерывный list.

Linked List
Как реализовать связный список на Python?

Минимальный односвязный список: каждый узел хранит значение и ссылку на следующий узел.

class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node

class LinkedList:
    def __init__(self):
        self.head = None

    def push_front(self, value):
        self.head = Node(value, self.head)

    def __iter__(self):
        cur = self.head
        while cur is not None:
            yield cur.value
            cur = cur.next

push_front — O(1). Обход — O(n).

✅ Что должен услышать проверяющий

  • Node хранит value и next
  • head
  • вставка в голову O(1)
  • обход через ссылки

🎯 Допвопрос

Что добавить для двусвязного списка?

Ответ на допвопрос

В каждом узле хранить не только next, но и prev; обычно ещё удобно хранить tail.

Для чего нужны аннотации типов в Python?

Аннотации типов описывают ожидаемые типы параметров, возвращаемых значений, переменных и т. д.

def total(prices: list[float]) -> float:
    return sum(prices)
  • улучшают читаемость и документацию кода;
  • помогают IDE с автодополнением и рефакторингом;
  • позволяют статическим анализаторам (mypy, pyright и др.) находить ошибки до запуска;
  • помогают описывать контракты API и generic-код.
По умолчанию аннотации не заставляют Python проверять типы при вызове функции.

✅ Что должен услышать проверяющий

  • документация/читаемость
  • IDE
  • статический анализ
  • не меняют семантику выполнения сами по себе

Typing
Может ли Python проверять типы на лету или это только статический анализ?

Сам язык остаётся динамически типизированным. Обычные type hints не включают автоматическую runtime-проверку.

Что такое декоратор в Python и как он работает изнутри?

Декоратор — callable, который получает функцию/класс и возвращает объект, который будет связан с исходным именем вместо него.

def deco(func):
    def wrapper(*args, **kwargs):
        print("before")
        result = func(*args, **kwargs)
        print("after")
        return result
    return wrapper

@deco
def add(a, b):
    return a + b

Синтаксический смысл:

add = deco(add)

Выражение декоратора вычисляется при выполнении определения функции (например, при импорте модуля), а wrapper — уже при последующих вызовах.

  • возвращает callable/замену

Как сделать декоратор с аргументами? Напишите пример.

Нужен ещё один уровень функции: фабрика декораторов → декоратор → wrapper.

from functools import wraps

def repeat(times):          # 1. принимает аргументы декоратора
    def decorator(func):    # 2. принимает функцию
        @wraps(func)
        def wrapper(*args, **kwargs):  # 3. вызывается вместо функции
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def hello(name):
    print(f"Hi, {name}")

@repeat(3) эквивалентно hello = repeat(3)(hello).

✅ Что должен услышать проверяющий

  • три уровня
  • внешняя функция получает параметры
  • средняя получает func

Как реализовать __eq__ так, чтобы сравнение работало корректно?
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

Хорошая практика:

  • сравнивать именно те поля, которые определяют логическое равенство;

Что такое ABC и @abstractmethod? Зачем они нужны?

from abc import ABC, abstractmethod

    def save(self, item) -> None:
        ...

class FileStorage(Storage):
    def save(self, item) -> None:

# Storage()      -> TypeError
# FileStorage()  -> OK

Нужны для явного интерфейса, раннего обнаружения неполной реализации и общего полиморфного API.

Абстрактный метод даже может содержать реализацию; важен сам статус abstract, пока подкласс его не переопределит.

Чем отличается итератор от итерируемого объекта?

Iterable (итерируемый объект) — объект, из которого можно получить итератор через iter(obj). Обычно он реализует __iter__.

Iterator (итератор) — объект, который хранит состояние обхода и выдаёт следующий элемент через __next__. Его __iter__() обычно возвращает self.

data = [10, 20, 30]  # iterable
it = iter(data)       # iterator
next(it)              # 10
next(it)              # 20

Список можно обходить много раз, создавая новые итераторы. Конкретный итератор обычно одноразовый: после исчерпания выдаёт StopIteration.

  • iterable → iter()
  • iterator → next()
  • __iter__ и __next__
  • итератор хранит состояние

Что такое генератор и как он экономит память?

Генератор — специальный итератор, который обычно создаётся функцией с yield или generator expression.

def squares(n):
    for i in range(n):
        yield i * i

g = squares(1_000_000)

При вызове генераторной функции тело не выполняется целиком: создаётся generator object. Он выполняется лениво до очередного yield, отдаёт значение и сохраняет своё состояние до следующего next().

Экономия памяти в том, что обычно не создаётся весь результат сразу; хранится состояние вычисления и текущие локальные ссылки.

Не надо обещать «всегда O(1) памяти»: генератор может сам хранить растущую структуру в локальной переменной. Точнее — он не обязан материализовать всю последовательность результатов.

✅ Что должен услышать проверяющий

  • yield
  • ленивое вычисление
  • generator — iterator
  • сохраняет состояние между yield
  • не материализует весь результат

Будет исключение:

TypeError: 'generator' object is not subscriptable

gen() возвращает generator object. У него есть протокол итератора (__iter__, __next__), но нет индексного доступа __getitem__, поэтому [1] неприменим.

Варианты получить второй элемент:

list(gen())[1]

# или лениво
it = gen()
next(it)      # 1
second = next(it)  # 2

✅ Что должен услышать проверяющий

  • TypeError
  • generator not subscriptable
  • gen() возвращает генератор
  • индексации нет
  • можно list() или next()

🎯 Допвопрос

Почему yield from [1, 2, 3] сам по себе корректен?

Ответ на допвопрос

Потому что список — iterable; yield from последовательно делегирует наружу значения 1, 2 и 3.

Практика
Напишите класс ProfileBlock: контекстный менеджер, замер времени блока и статистика count/min/max/avg.

Один из аккуратных вариантов:

import time
from types import TracebackType

class ProfileBlock:
    def __init__(self, name: str):
        self.name = name
        self._start: float | None = None
        self._durations: list[float] = []

    def __enter__(self) -> "ProfileBlock":
        if self._start is not None:
            raise RuntimeError("ProfileBlock already started")
        self._start = time.perf_counter()
        return self

    def __exit__(
        self,
        exc_type: type[BaseException] | None,
        exc_value: BaseException | None,
        traceback: TracebackType | None,
    ) -> bool:
        if self._start is None:
            raise RuntimeError("ProfileBlock not started")

        self._durations.append(time.perf_counter() - self._start)
        self._start = None

        # False => не подавляем исключение из блока with
        return False

    def get_stats(self) -> dict[str, int | float | None]:
        if not self._durations:
            return {
                "count": 0,
                "min": None,
                "max": None,
                "avg": None,
            }

        return {
            "count": len(self._durations),
            "min": min(self._durations),
            "max": max(self._durations),
            "avg": sum(self._durations) / len(self._durations),
        }

block = ProfileBlock("math section")
with block:
    time.sleep(0.1)
    result = 2 ** 10

print(block.get_stats())

Если один и тот же объект block использовать в нескольких with, список _durations накопит статистику всех запусков.

Что важно проговорить: __enter__ возвращает объект после as; __exit__ вызывается и при нормальном выходе, и при исключении; return False не подавляет исключение.

✅ Что должен услышать проверяющий

  • __enter__ запускает perf_counter
  • __exit__ фиксирует duration
  • возвращаем self
  • статистика count/min/max/avg
  • return False не подавляет исключение

🎯 Допвопрос

Что получает __exit__ при исключении внутри with?

Ответ на допвопрос

Три аргумента про исключение: тип, объект исключения и traceback. Если исключения не было — все три равны None. Истинное значение из __exit__ подавляет исключение, ложное — пропускает дальше.
