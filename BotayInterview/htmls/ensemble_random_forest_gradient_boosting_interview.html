Ансамблирование — это объединение предсказаний нескольких моделей в одно итоговое предсказание.

Идея: несколько неидеальных моделей могут вместе работать лучше одной, особенно если их ошибки не полностью совпадают.

  • Bagging — модели обучаются независимо, затем их ответы усредняются / голосуются. Главный пример — Random Forest.
  • Boosting — модели строятся последовательно, новая модель исправляет ошибки текущего ансамбля.
  • Stacking — предсказания базовых моделей подаются мета-модели, которая учится их комбинировать.
Ансамблирование повышает качество и устойчивость за счёт объединения нескольких моделей.
На собесе: «Bagging в первую очередь уменьшает variance, boosting — последовательно уменьшает ошибку и обычно хорошо снижает bias».

Random Forest — ансамбль деревьев решений, в котором деревья специально делают разными.

  1. Для каждого дерева строится bootstrap-выборка из исходных объектов.
  2. В каждом узле при поиске split рассматривается только случайное подмножество признаков.
  3. Строится много деревьев.
  4. Предсказания объединяются.

Регрессия:

ŷ = (1 / T) · Σ fₜ(x)

Классификация: обычно усредняются вероятности классов, после чего выбирается класс с максимальной вероятностью.

Случайность есть в двух местах: объекты + признаки. Это декоррелирует деревья.

Глубокое дерево обычно имеет низкий bias, но высокий variance: оно легко подстраивается под train и сильно меняется при небольшом изменении данных.

Random Forest усредняет много разных деревьев:

f_RF(x) = (1 / T) · Σ fₜ(x)

Случайные ошибки отдельных деревьев частично компенсируют друг друга, поэтому variance ансамбля становится меньше.

Но усреднение помогает только если деревья не полностью одинаковые. Поэтому используются:

  • разные bootstrap-выборки;
  • случайные подмножества признаков.
Random Forest борется с переобучением одиночного дерева прежде всего через уменьшение variance.

Bootstrap — случайное семплирование с возвращением.

Исходные объекты: A B C D E
Bootstrap: A C C E B

Объект C может попасть несколько раз, а D — вообще не попасть.

Если из N объектов сделать N выборов с возвращением, вероятность конкретному объекту не попасть ни разу:

(1 − 1/N)N ≈ e−1 ≈ 0.368

Поэтому в bootstrap sample в среднем около 63.2% уникальных объектов, а около 36.8% остаются вне выборки.

Объекты, не попавшие в bootstrap конкретного дерева, называются out-of-bag (OOB) объектами для этого дерева.

Упрощённо ожидаемую ошибку можно представить как:

Error ≈ Bias² + Variance + Noise

Bias — систематическая ошибка из-за слишком сильных ограничений модели. Высокий bias связан с underfitting.

Variance — чувствительность модели к конкретной обучающей выборке. Высокий variance связан с overfitting.

простая модель → ↑ bias, ↓ variance
сложная модель → ↓ bias, ↑ variance
Tradeoff — поиск такой сложности модели, при которой мы не слишком недообучаемся и не слишком подгоняемся под train.

Нюанс: нельзя говорить «линейная регрессия всегда имеет высокий bias». Если реальная зависимость линейна, её bias может быть маленьким.
RF особенно силён в снижении variance, boosting — в последовательном снижении bias.

Классический вариант — Mean Decrease in Impurity (MDI).

Если split по признаку сильно уменьшил impurity, признак получает большую важность:

ΔI = I(parent) − (NL/N)·I(L) − (NR/N)·I(R)

Уменьшение impurity суммируется по узлам и затем по деревьям.

В sklearn:

model.feature_importances_

Альтернатива — permutation importance: перемешать значения признака и посмотреть, насколько ухудшилась метрика.

MDI может завышать важность некоторых признаков, например признаков с большим числом возможных значений.

Для каждого дерева часть объектов не попадает в его bootstrap sample — это его OOB-объекты.

Чтобы оценить объект xᵢ:

  1. берём только деревья, которые не обучались на xᵢ;
  2. получаем их предсказания;
  3. агрегируем их;
  4. сравниваем с истинным yᵢ.
OOB — почти встроенная validation-оценка без отдельного отрезания validation set.

Шум может испортить отдельное дерево, но из-за bootstrap и случайного выбора признаков он обычно не воздействует одинаково на все деревья.

Затем ответы большого числа деревьев усредняются, и часть случайных ошибок сглаживается.

разные данные + разные признаки + усреднение → ниже variance
Random Forest не неуязвим: сильный label noise, много мусорных признаков или систематический шум всё равно ухудшают качество.

Зависит от реализации.

Классический подход — сначала сделать импутацию:

NaN → median / most_frequent / KNN / другой imputer → Random Forest

В современных реализациях некоторых библиотек есть нативная обработка пропусков. Например, актуальные реализации sklearn Random Forest умеют обучать направление для NaN при split.

На собеседовании лучше не говорить категорично «Random Forest не умеет NaN». Уточняем конкретную библиотеку и версию.

Плюсы

  • надёжный baseline;
  • мало preprocessing;
  • не нужен scaling;
  • ловит нелинейности и interactions;
  • устойчивее одиночного дерева;
  • есть OOB-оценка;
  • деревья легко обучать параллельно;
  • обычно проще тюнить, чем boosting.

Минусы

  • часто уступает хорошо настроенному boosting на табличных данных;
  • может занимать много памяти;
  • тысячи деревьев замедляют inference;
  • хуже интерпретируется, чем одно дерево;
  • MDI importance может быть вводящей в заблуждение;
  • как и другие деревья, плохо экстраполирует.
  • Параллелить деревья: например, n_jobs=-1 в sklearn.
  • Уменьшить n_estimators, если деревьев уже достаточно.
  • Ограничить max_depth или max_leaf_nodes.
  • Увеличить min_samples_leaf / min_samples_split.
  • Уменьшить max_features.
  • Использовать max_samples < 1.0, если полная выборка не нужна каждому дереву.
  • Рассмотреть ExtraTrees, где split выбираются более случайно и обучение часто дешевле.
Главное инженерное преимущество RF: деревья независимы, поэтому ансамбль хорошо параллелится.

Gradient Boosting строит ансамбль последовательно:

FM(x) = F0(x) + ηf₁(x) + ηf₂(x) + ... + ηfM(x)

Каждое новое дерево пытается улучшить уже существующую модель.

Для произвольной differentiable loss строятся pseudo-residuals — отрицательные градиенты:

rim = − ∂L(yᵢ, F(xᵢ)) / ∂F(xᵢ)

Новое дерево учится приближать это направление ошибки.

Gradient Boosting — это градиентный спуск не по обычным весам, а в пространстве функций: новое дерево становится очередным шагом.

Самая важная связка для понимания: learning_rate ↔ количество деревьев ↔ сложность дерева.

Learning rate η определяет, какую долю коррекции нового дерева мы добавляем:

Fm(x) = Fm−1(x) + η · fm(x)

Маленький learning rate:

  • делает шаги осторожнее;
  • часто улучшает generalization;
  • требует больше деревьев;
  • увеличивает время обучения.
learning_rate ↓ ⇒ обычно n_estimators ↑
Learning rate — shrinkage: мы уменьшаем вклад каждого отдельного дерева.

Boosting может переобучаться, поэтому его ограничивают несколькими способами:

  • маленький learning_rate;
  • неглубокие / небольшие деревья;
  • subsample объектов;
  • сэмплирование признаков;
  • ограничения размера листьев;
  • L1/L2-регуляризация;
  • early stopping.
train loss продолжает ↓, validation loss начал ↑ → пора останавливаться
В boosting важен не один «анти-overfit параметр», а баланс шага, числа деревьев и сложности каждого дерева.

Регуляризация — механизмы, которые ограничивают способность ансамбля слишком точно подгонять train.

  • Shrinkage: маленький learning_rate.
  • Ограничение деревьев: max_depth, num_leaves, минимальный размер листа.
  • Randomization: subsample, column sampling.
  • L2: штраф на большие веса листьев.
  • L1: штраф по абсолютным значениям.
  • Split constraints: минимальный gain для разбиения.
  • Early stopping.
Objective = Loss + Regularization

ŷ = (f₁ + f₂ + ... + f₁₀₀) / 100

После удаления первого дерева:

Этот вопрос проверяет главное различие: bagging — параллельный/независимый, boosting — последовательный/зависимый.

Плюсы

  • очень сильное качество на табличных данных;
  • ловит нелинейности и взаимодействия признаков;
  • не требует scaling;
  • может оптимизировать разные loss;
  • современные реализации умеют missing values, categorical features и развитую регуляризацию.

Минусы

  • больше гиперпараметров;
  • легче переобучить, чем RF;
  • деревья строятся последовательно, поэтому хуже параллелятся на уровне ансамбля;
  • чувствителен к learning rate и сложности деревьев;
  • тюнинг обычно сложнее.
Random Forest — надёжный baseline. Gradient Boosting — частый кандидат на максимальное качество для табличных данных.

CatBoost

Особенно известен нативной работой с категориальными признаками, ordered statistics и режимом Ordered Boosting, которые помогают уменьшать target leakage / prediction shift. Характерная реализация — симметричные деревья.

XGBoost

Очень зрелая реализация с развитой регуляризацией и большим набором параметров:

Objective = Loss + Ω(model)

Типичные механизмы: L1/L2, gamma, min_child_weight, row/column sampling. Есть histogram-based построение деревьев и native categorical features.

LightGBM

Характерная особенность — leaf-wise рост: на каждом шаге делится тот лист, который даёт наибольшее улучшение.

выбираем не «следующий уровень», а лучший текущий лист

Это часто быстро уменьшает loss, но требует аккуратно ограничивать num_leaves, max_depth и min_data_in_leaf, особенно на небольших данных.

Ответ за 20 секунд: «Все три — реализации gradient boosted trees. XGBoost известен универсальностью и развитой регуляризацией, LightGBM — histogram-based обучением и leaf-wise ростом, что делает его быстрым на больших данных, CatBoost — сильной нативной обработкой категориальных признаков, ordered statistics и Ordered Boosting».
