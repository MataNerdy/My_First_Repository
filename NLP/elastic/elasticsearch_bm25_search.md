# Поиск товаров в Elasticsearch: обратный индекс, BM25 и метрики

Этот пример показывает минимальный поисковый сервис по каталогу товаров. Данные хранятся в Elasticsearch, а приложение отправляет туда запрос и получает отсортированные `product_id`.

Elasticsearch сам строит обратный индекс для полей типа `text`: он хранит соответствие «термин → документы и статистики по ним». Поэтому при запросе не нужно перебирать весь каталог. Для полнотекстовых полей Elasticsearch использует BM25 по умолчанию; в примере настройка BM25 указана явно с `k1=1.2` и `b=0.75`.

Скрипт [elasticsearch_bm25_search.py](elasticsearch_bm25_search.py) берёт потоковый срез открытого Amazon Shopping Queries / ESCI, индексирует реальные карточки товаров и сравнивает Elasticsearch BM25 с упрощённым поиском по обратному индексу без ранжирования.

## Подготовка Python-окружения через uv

В папке с файлами создайте виртуальное окружение и установите зависимости:

```bash
uv venv
source .venv/bin/activate
uv pip install "elasticsearch>=8,<10" datasets pandas
```

На Windows активируйте окружение так:

```powershell
.venv\Scripts\Activate.ps1
```

После этого все команды `python` ниже будут использовать пакеты из `.venv`.

## Что нужно установить

Нужен запущенный Elasticsearch 8+ или Elastic Cloud, а также Python 3.10+. Python-зависимости уже установлены на предыдущем шаге через `uv`.

Для локальной учебной среды можно запустить один узел без безопасности. Это допустимо только на своём компьютере, не в публичной сети:

```bash
docker run --name elasticsearch-demo --rm -p 9200:9200 \
  -e discovery.type=single-node \
  -e xpack.security.enabled=false \
  docker.elastic.co/elasticsearch/elasticsearch:8.19.0
```

Для Elastic Cloud вместо этого сохраните URL и API key в переменных окружения:

```bash
export ELASTICSEARCH_URL='https://...'
export ELASTIC_API_KEY='...'
```

## Запуск

```bash
export ELASTICSEARCH_URL='http://localhost:9200'
python elasticsearch_bm25_search.py --recreate-index
```

Флаг `--recreate-index` намеренно обязателен, если индекс `products-esci-demo` уже существует: скрипт удалит и создаст заново только этот учебный индекс. `--rows 3000` ограничивает объём исходного датасета, а `--queries 100` — число запросов для проверки.

## Как устроен индекс

В скрипте создаются поля:

- `title` и `description` — `text`, в них Elasticsearch строит обратный индекс и считает BM25;
- `product_id` и `brand` — `keyword`, точные значения для фильтров и идентификации.

У `title` в запросе вес `^3`, поэтому совпадение в названии сильнее совпадения в длинном описании:

```python
"multi_match": {
    "query": query,
    "fields": ["title^3", "description"],
    "type": "best_fields",
}
```

В проде обычно добавляют фильтры `filter` по наличию, цене, категории и региону. Они не меняют BM25-оценку, но уменьшают множество допустимых товаров. Синхронизировать индекс стоит событиями из PostgreSQL/MySQL через очередь, а не прямым обновлением из пользовательского запроса.

## Сравнение качества

ESCI содержит оценку пары «запрос — товар». В примере положительными считаются только товары с меткой `E` (`Exact`). Обе функции поиска должны соблюдать один контракт:

```python
search(query: str, limit: int) -> list[str]
```

Это даёт честное сравнение на одинаковых запросах и одинаковом `k`.

| Метрика | Что показывает |
| --- | --- |
| `Precision@10` | Доля точных товаров среди первых десяти результатов. |
| `Recall@10` | Какую долю всех известных точных товаров удалось вернуть в топ-10. |
| `MRR@10` | Насколько высоко расположен первый точный товар. |
| `nDCG@10` | Качество всего порядка результатов с большим весом верхних позиций. |

Baseline в скрипте берёт объединение posting lists обратного индекса и сортирует `product_id`. Он намеренно **не ранжирует** результаты и нужен только как нижняя граница. Elasticsearch должен показывать существенно более высокие метрики, потому что учитывает частоту терминов, редкость, длину полей и вес заголовка через BM25.

## Что менять для настоящего маркетплейса

1. Разделите индексы по окружениям и используйте alias для безостановочного переиндексирования.
2. Добавьте язык-анализатор, синонимы, исправление опечаток и отдельные поля для артикулов и брендов.
3. Сначала проверяйте изменения на отложенной выборке с метками, а не только на нескольких красивых запросах вручную.
4. После BM25 можно переранжировать небольшой top-k моделью или объединить его с векторным поиском.
