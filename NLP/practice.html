Шаг 1 · закрыт

Классификатор языка ru / en / es

Исходный вариант на fastai ты переписала на чистый PyTorch и разобрала весь путь данных.

CSV → Dataset → DataLoader → model → CrossEntropyLoss → backward → validation / test

Bag of Characters

Символьный словарь строится только по train. Токен <UNK> получает индекс 0, а остальные символы из text.lower() сортируются.

Каждый текст превращается в вектор частот символов, нормированный на длину строки.

Главное ограничение: порядок символов полностью теряется. hello и olleh дают одинаковое представление.
Архитектура Параметры Основная идея
LanguageClassifier 9 987 Базовая полносвязная сеть
LayerNormSwish 28 419 LayerNorm и нелинейность Swish
SwiGLUClassifier 28 659 Проекция делится на value и gate
Лучший результат SwiGLU: test loss = 0.0220, accuracy = 0.9940 — 1491 из 1500. Русский: 500/500. Английский: 6 ошибок в испанский. Испанский: 3 ошибки в английский. F1 для en/es ≈ 0.991.
Что мы разобрали вокруг обучения
  • CrossEntropyLoss принимает logits: Softmax перед loss не нужен.
  • argmax(dim=1) выбирает класс отдельно для каждого объекта батча.
  • model.eval() меняет поведение слоёв, но не отключает вычисление градиентов.
  • Для инференса нужен torch.no_grad() или torch.inference_mode().
  • zero_grad(set_to_none=True) очищает накопленные градиенты.
  • DataLoader не балансирует классы. shuffle=True только перемешивает данные.
  • Train обучает модель, validation помогает выбирать архитектуру и гиперпараметры, test используется для финальной оценки.
Ошибки модели и проблема confidence

Ошибки были почти только между английским и испанским: Good quality replacement, Nice phone, great price, Salen muy bien! Divertido.

Иногда неправильное предсказание имело confidence около 0.99.

Вывод: Softmax показывает уверенность модели внутри её собственной картины мира, а не вероятность того, что модель действительно поняла текст.

Что сохраняется в checkpoint 
{
    "model_state_dict": ...,
    "model_class": "SwiGLUClassifier",
    "vocabulary": vocabulary,
    "hidden_size": HIDDEN_SIZE,
    "id_to_language": ID_TO_LANGUAGE
}

При загрузке сначала создаётся правильная архитектура через registry, затем вызываются load_state_dict() и eval().

Зачем классификатор поисковой системе: он может фильтровать корпус по языку или маршрутизировать запрос в нужный индекс и нужную модель.
Шаг 2 · закрыт

Очистка веб-корпуса в духе FineWeb

сырой HTML → извлечение текста → нормализация → quality-фильтры → PII → дедупликация

Извлечение текста

BeautifulSoup удаляет script, style, nav, footer, header, aside, noscript, form и cookie/banner-блоки.

Текст извлекается через get_text(separator="\n", strip=True). Trafilatura рассматривалась как более умный экстрактор основного содержимого страницы.

Проверка Что измеряет Порог
check_min_length len(text) > 50 Иначе too_short
repeated_line_ratio Доля строк из повторяющихся групп >= 0.5
short_lines_ratio Доля непустых строк короче 30 символов >= 0.5
Краш-тест фильтров: документ 1 принят; документ 2 отклонён как too_short + short_lines; документ 3 — как repeated_lines; документ 4 — как too_short + short_lines. У меню repeated ratio = 1.0, у статьи = 0.0.

Маскирование PII

anonymize_pii() заменяет email и телефон на [EMAIL] и [PHONE], а также возвращает количество замен. 

Напишите Анне на [EMAIL]
или позвоните по номеру [PHONE].

{"emails": 1, "phones": 1}
Важная ловушка: второй subn должен получать результат первого. Если снова передать исходный text, замаскированный email появится обратно. Regex остаются эвристикой: возможны false positive и false negative.

Дедупликация

Тип Как работает
Exact duplicates Нормализация пробелов → lowercase → UTF-8 → SHA-256. В seen_hashes сохраняется первое вхождение.
Near duplicates Word n-grams → множества → Jaccard: |A ∩ B| / |A ∪ B|.
Большой корпус MinHash приближённо оценивает Jaccard. Его мы сознательно отложили до понимания обычной версии.
Какие функции мы написали

normalize_whitespace, repeated_line_ratio, short_lines_ratio, get_quality_issues, anonymize_pii, get_text_hash, remove_exact_duplicates, get_word_ngrams, jaccard_similarity, are_near_duplicates, remove_near_duplicates.

Крайние случаи Jaccard
  • При пустом объединении нужна отдельная обработка.
  • кот и пёс при n=3 оба не создают n-грамм, но не являются дублями.
  • Если n-грамм нет, сравниваем нормализованные строки напрямую.
  • n=2, threshold=0.4 удобны для коротких учебных текстов.
  • n=3, threshold=0.9 — более осторожная дедупликация.
  • При n <= 0 логично выбрасывать ValueError.
Шаг 3 · закрыт

BPE, WordPiece и Unigram / SentencePiece

Токенизаторы сравнивались по одному маршруту: encoding → input_ids → tokens → decode. При этом загружались файлы токенизатора, а не веса большой Qwen.

Токенизатор Семейство Что заметили
Qwen/Qwen3.6-27B Byte-level BPE Маркер Ġ и байтовые фрагменты русского текста вида Ð¡Ñ...
bert-base-multilingual-cased WordPiece ## означает продолжение слова
google/mt5-small Unigram + SentencePiece ▁ отмечает границу или начало слова
Русский пример про беспроводные наушники Qwen разбил на 34 токена. Внутренние токены выглядели странно, но decode(input_ids) полностью восстановил исходную строку.
Источник истины — decode. convert_ids_to_tokens() показывает внутреннее устройство словаря и не обязан выдавать красивые человекочитаемые кусочки.
Зачем отдельно обрабатывать специальные токены

<|user|>, <|assistant|>, <|end|> несут структуру диалога.

Их сначала выделяют и сохраняют целиком, а обычный текст токенизируют отдельно. Посимвольное разбиение в учебном примере было лишь визуальной заглушкой настоящего BPE.

Почему BPE нельзя подставить вместо BoC одной строкой

BoC выдаёт фиксированный вектор [batch, 152]. BPE выдаёт последовательность переменной длины [batch, seq_len].

token IDs → Embedding → padding и mask → pooling → classifier
Шаг 4 · текущий главный блок

TF-IDF, cosine, обратный индекс и BM25

Практика началась с корпуса из трёх документов: lower() + split(), отсортированный словарь и ручная матрица «документы × термины».

Величина Формула Смысл
TF count, count / |d|, 1 + log(count) или binary Частота термина в документе
IDF log(N / DF) Редкость термина в корпусе
TF-IDF TF × IDF Вес термина для конкретного документа
Cosine similarity (a · b) / (||a|| ||b||) Сходство направлений векторов
Примеры cosine: Document 1 vs 2 → 0.152; Document 1 vs 3 → 0.065. В функции проверялись одинаковая длина векторов и нулевая норма.

Как устроен TF-IDF-поиск

обратный индекс → документы-кандидаты → TF-IDF запроса → cosine → сортировка
Обратный индекс и ранжирование не конкурируют. Индекс быстро отвечает, в каких документах встречаются термины. TF-IDF или BM25 определяет, какие из этих документов нужно показать выше.

BM25

BM25 не строит TF-IDF-векторы и не считает cosine. Он суммирует вклад терминов запроса с учётом:

  • редкости термина;
  • частоты в документе;
  • насыщения TF;
  • длины документа.
IDF(t) =
log(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))


score(q, d) =
Σ IDF(t) ·
  f(t,d) · (k1 + 1)
  ─────────────────────────────────
  f(t,d) + k1 · (1 - b + b·|d|/avgdl)
Для учебного запроса «кот диване» BM25 scores документов составили: 0.482, 0.656, 1.286, 0.0.
Нюанс нормализации длины: если просто поделить весь TF-IDF-вектор документа на его длину, cosine similarity не изменится. Масштаб сократится одновременно в числителе и знаменателе. BM25 учитывает длину документа внутри своей формулы.

Как будем измерять качество поиска

Сначала создаём маленькую ручную разметку релевантности: 

qrels = {
    "беспроводные наушники": {2, 5, 8},
    "телефон до 30000": {1, 4},
}

После этого считаем Precision@k, Recall@k, NDCG@k, а затем MRR и MAP.

TF-IDF, BM25 и vector search нужно сравнивать на одной и той же разметке.

Что заботать дальше — без перегруза

Главная ветка: поиск

  • Закончить end-to-end TF-IDF: запрос → вектор → cosine → ranking.
  • Написать обратный индекс: term → документы и частоты.
  • Реализовать полноценный BM25: кандидаты → score → сортировка.
  • Собрать ручную разметку релевантности.
  • Посчитать P@k, R@k, NDCG, MRR и MAP.
  • Сравнить TF-IDF, BM25 и vector search.
  • Только после этого перейти к RAG: retrieval → context → generation.

Ветка классификации

  1. Добавить character n-grams, чтобы вернуть локальный порядок символов.
  2. Построить BPE + Embedding + mask + pooling + classifier.
