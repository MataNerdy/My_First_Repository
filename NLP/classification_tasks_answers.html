Классификация языка в PyTorch

Все задания из ноутбука classification_training.ipynb, решения Любови, уточнения и результаты экспериментов.

CSV → Dataset → DataLoader → model → loss → backward → optimizer → validation → test → inference
1. Данные 2. Bag of Characters 3. Dataset 4. DataLoader 5. Модели 6. Эпоха 7. Обучение 8. Test 9. Сохранение

Важные уточнения к ноутбуку

  • Dataset — не словарь, а индексируемый интерфейс над данными.
  • DataLoader не балансирует классы автоматически: shuffle=True только перемешивает примеры.
  • collate_fn собирает элементы в батч; выбор объектов задают sampler и batch_sampler.
  • model.eval() не отключает градиенты. Для этого нужен torch.no_grad() или torch.inference_mode().
  • SwiGLU использует SiLU: value * silu(gate). С SELU это уже другой блок.
  • При сохранении экспериментальной модели нужно сохранять название архитектуры, иначе нельзя надёжно восстановить объект модели.

Задание 2. Bag of Characters

Задание

Сравнить векторы для Hello, hello и olleh. Объяснить совпадения и потерянную информацию.

Ответ Любови

Порядок букв не учитывается: слово приводится к нижнему регистру, разбирается на символы, для каждого считается количество, затем значения нормируются на длину.

h → 1/5 = 0.2

e → 1/5 = 0.2

l → 2/5 = 0.4

o → 1/5 = 0.2

  • Hello и hello совпадают из-за text.lower().
  • hello и olleh совпадают, потому что представление не хранит позиции.
  • После нормирования теряется и абсолютная длина: hello и hellohello имеют одинаковые относительные частоты.
  • features /= len(normalized_text) делит весь вектор; нулевые координаты просто остаются нулями.

Почему словарь должен быть общим

Модель обучает отдельный вес для каждой координаты. Если на train features[2] означает частоту b, а в собственном словаре validation та же координата означает c, модель получает признаки с другим смыслом. При разном размере будет явная ошибка формы; при одинаковом — тихая смысловая ошибка.

Пустая строка

Цикл не выполняется, условие if normalized_text не даёт делить на ноль. Возвращается вектор из 152 нулей.

Неизвестный символ

.get(character, 0) отправляет его в координату <UNK>. Для строки из одного неизвестного символа features[0] = 1.0.

Пять самых частых символов

for index, value in zip(indices, values):

Logits и argmax

logits.shape == [128, 3]: строки — объекты, столбцы — классы. argmax(dim=1) проходит по трём столбцам каждого объекта, возвращая 128 меток. Форма результата — [128], а с keepdim=True была бы [128, 1].

Почему без Softmax в forward

CrossEntropyLoss принимает сырые логиты и численно устойчиво объединяет LogSoftmax + NLLLoss. Если применить Softmax заранее, loss воспримет вероятности как новые логиты и ещё раз выполнит преобразование. Для выбора класса Softmax не нужен: он меняет значения, но не позицию максимума.

Задание 6. Цикл одной эпохи

Задание

Восстановить пять шагов обучения и объяснить режимы модели, отключение градиентов и усреднение loss.

optimizer.zero_grad(set_to_none=True)

logits = model(features)
loss = loss_function(logits, labels)

loss.backward()
optimizer.step()
ОперацияРоль
model.train()Dropout работает; BatchNorm использует и обновляет статистики батча.
model.eval()Dropout выключен; BatchNorm использует накопленные статистики.
torch.no_grad()Не строит граф и не вычисляет градиенты; экономит память и время.
loss.backward()Вычисляет производные и записывает их в parameter.grad.
optimizer.step()Обновляет веса по накопленным градиентам.

eval() не отключает autograd и сам по себе не запрещает optimizer.step(). Накопленные статистики BatchNorm — не то же самое, что его обучаемые weight и bias.

Зачем set_to_none=True

zero_grad(set_to_none=True) устанавливает parameter.grad = None вместо заполнения существующего тензора нулями. При следующем backward градиент создаётся заново; это обычно экономнее.

Подсчёт правильных ответов

total_correct += (
    logits.argmax(dim=1) == labels
).sum().item()

Сначала создаётся булева маска, затем sum() считает True как единицы, а .item() переводит скалярный тензор в число Python.

Средний loss по объектам

total_loss += loss.item() * batch_size
...
average_loss = total_loss / total_examples

CrossEntropy возвращает среднее внутри батча. Умножение восстанавливает сумму, после чего деление на общее число объектов даёт честное среднее по примерам. Иначе последний батч из 4 объектов получил бы такой же вес, как полный батч из 128.

Задание 7. Обучение и диагностика

Задание
  1. Сравнить train loss и validation loss.
  2. Изменить ширину, learning rate или число эпох.
  3. Определять недообучение и переобучение.
  4. Объяснить, почему после смены архитектуры нужно заново создать model и optimizer.
Диагностика
  • Недообучение: оба loss остаются большими, модель плохо работает даже на train. Если оба уверенно падают, обучение, возможно, просто ещё не завершено.
  • Нормальное обучение: оба уменьшаются, validation достигает хорошего минимума, разрыв остаётся умеренным.
  • Переобучение: train loss продолжает падать, а validation loss после минимума устойчиво растёт.

Одно плато validation ещё не доказывает переобучение. Большой разрыв «низкий train — высокий validation» является признаком generalization gap.

Восстановление

MODEL_REGISTRY = {
    "LanguageClassifier": LanguageClassifier,
    "LayerNormSwishClassifier": LayerNormSwishClassifier,
    "SwiGLUClassifier": SwiGLUClassifier,
}

checkpoint = torch.load(
    ARTIFACT_PATH,
    map_location=device,
)

model_class = MODEL_REGISTRY[checkpoint["model_class"]]

loaded_model = model_class(
    input_size=len(checkpoint["vocabulary"]),
    hidden_size=checkpoint["hidden_size"],
    output_size=len(checkpoint["id_to_language"]),
).to(device)

loaded_model.load_state_dict(checkpoint["model_state_dict"])
loaded_model.eval()

Это подтверждает согласованность всей цепочки: архитектуры, весов, словаря, индексов признаков и соответствия меток языкам.

Финальная карта знаний

  • Словарь и остальные обучаемые преобразования строятся только по train.
  • Dataset возвращает один объект, DataLoader формирует батч.
  • Модель выдаёт логиты, CrossEntropy сама выполняет нужное log-softmax-преобразование.
  • backward() вычисляет градиенты; step() обновляет параметры.
  • eval() и no_grad() решают разные задачи.
  • Validation выбирает модель; test один раз оценивает выбранное решение.
  • Accuracy дополняют confusion matrix, per-class метрики и ручной анализ ошибок.
  • Для воспроизводимого inference нужны веса, архитектура, размерности, словарь и mapping меток.
